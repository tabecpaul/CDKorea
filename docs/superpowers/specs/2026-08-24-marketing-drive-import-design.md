# Career Direct Korea Drive 패키지 가져오기와 Canva 수정본 설계

- 상태: 사용자 범위 승인, 문서 검토 대기
- 기준 문서: `2026-08-24-marketing-content-dashboard-design.md`
- 구현 단계: 마케팅 콘텐츠 대시보드 5단계

## 1. 목적과 범위

ChatGPT Work가 Google Drive 운영 폴더에 준비한 콘텐츠 패키지를 관리자 대시보드로 안전하게 가져오고, 관리자가 Canva에서 수정한 카드별 PNG를 새 버전으로 보존한다. 이 단계는 콘텐츠를 게시하거나 최종 승인하지 않는다.

포함 범위는 패키지 규격, 수동 및 예약 가져오기, 파일 검증, 수정본 업로드, 버전 보존과 감사 기록이다. Meta 게시, 네이버 자동 발행, 승인·승인 취소와 외부 공개 미디어 URL은 후속 단계로 남긴다.

## 2. 확정 원칙

- Drive 운영 폴더는 공개 공유로 바꾸지 않는다.
- 실제 Drive 인증정보와 비밀값은 저장소·DB·로그에 기록하지 않는다.
- 같은 패키지를 수동 가져오기와 예약 작업이 동시에 처리해도 하나의 버전만 생성한다.
- 기존 버전과 사용자 파일은 덮어쓰거나 삭제하지 않는다.
- 기본 카드 수는 5장이며, `flexible-card-news-design-spec.md`에 따라 메시지 구조상 필요한 경우 4~8장을 허용한다.
- `소명은 직업보다 큽니다` 5장은 브랜드 기준 사례이지 모든 콘텐츠의 고정 좌표 템플릿이 아니다.
- Canva 수정본 업로드는 원고·CTA·UTM을 암묵적으로 바꾸지 않는다.
- 이 단계 배포 후에도 자동 발행은 비활성 상태다.

## 3. 콘텐츠 패키지

Drive의 각 콘텐츠 폴더에는 `content-package.json` 하나를 둔다. manifest는 다음 값만 참조한다.

- `schemaVersion`, 전역 고유 `packageId`
- 콘텐츠 `slug`, 제목, 캠페인 키, 승인된 CTA 종류, 실제 네이버 카테고리
- 네이버 원고, Meta 문안, Threads 문안 파일 ID
- 순서가 고정된 카드 PNG 파일 ID 4~8개
- 채널별 KST 발행 시각, 수동·자동 모드, UTM URL
- 선택적인 Canva 디자인 URL과 Drive 폴더 ID

원고 내용을 JSON에 중복 저장하지 않고 지정된 Drive 파일에서 읽는다. URL 대신 Drive 파일 ID를 사용하며, 폴더 밖 임의 파일을 참조하지 못하도록 운영 폴더의 상위 관계를 확인한다.

허용값은 기존 마케팅 도메인의 채널·상태 allowlist와 승인된 CTA 목록을 재사용한다. 알 수 없는 필드는 호환성을 위해 무시하지 않고 거부한다.

## 4. 가져오기 흐름

1. 관리자 수동 API 또는 인증된 예약 작업이 동일한 import 서비스를 호출한다.
2. manifest의 크기, JSON 구조, 스키마 버전과 허용 필드를 검증한다.
3. `packageId` 중복을 원자적으로 선점한다.
4. Drive 파일의 존재, 소유 범위, MIME, 크기와 메타데이터를 확인한다.
5. 텍스트 파일을 읽어 길이·형식·필수 내용을 검증한다.
6. PNG를 읽으며 SHA-256, 바이트 크기, 1080×1350 규격과 순서를 확인한다.
7. 한 DB transaction에서 콘텐츠, 새 버전, 자산, 채널 일정을 저장하고 현재 버전을 갱신한다.
8. 성공 또는 실패 결과를 `marketing_audit_logs`와 예약 작업 실행 기록에 남긴다. 파일 본문과 비밀값은 로그에서 제외한다.

가져온 버전의 초기 상태는 `review_pending`이다. 다만 manifest가 콘텐츠 제작 전 제안만 담는 형식은 이번 단계에 포함하지 않고, 완성 패키지만 가져온다.

## 5. 중복 방지와 데이터 변경

현재 스키마에는 전역 `packageId`를 원자적으로 보호하는 필드가 없다. `marketing_content_versions`에 nullable `source_package_id`를 추가하고, 값이 있는 행만 대상으로 unique index를 둔다. 기존 데이터에는 영향을 주지 않는다.

마이그레이션 전에 Production 대상이 `fytkptzbnhfsqsktmzpx`인지 Vercel과 GitHub secret 양쪽에서 다시 확인한다. 잘못된 ref이거나 확인할 수 없으면 DB 적용을 중지한다. 적용 후 공개 역할 권한 차단과 Supabase Security Advisor 오류 0건을 다시 확인한다.

같은 `packageId`의 재요청은 기존 성공 결과를 반환하며 새 버전을 만들지 않는다. 먼저 실패한 요청은 성공 데이터가 생성되지 않았으므로 원인을 고친 뒤 다시 처리할 수 있다.

## 6. Canva 수정본 업로드

콘텐츠 상세 화면에서 관리자는 현재 버전의 Canva 링크를 열고, 수정한 카드별 PNG를 순서대로 업로드한다. 서버는 다음을 모두 확인한다.

- 관리자 세션과 대상 콘텐츠 존재
- PNG MIME과 실제 파일 시그니처 일치
- 각 파일 1080×1350
- 4~8장, 중복 순서 없음, 설정된 파일 크기 한도 이내
- 현재 버전이 발행 완료 상태가 아님

검증을 통과하면 Drive의 해당 콘텐츠 하위에 새 버전 폴더를 만들고 파일을 저장한 뒤, DB에 새 `review_pending` 버전과 자산 해시를 기록한다. 원고, CTA, UTM과 채널 일정 초안은 직전 버전에서 명시적으로 복사한다. 이전 승인 또는 일정은 이 단계에서 변경하지 않으며, 승인 무효화와 예약 취소는 6단계 명령 서비스에서 원자적으로 처리한다.

업로드 중 일부 파일이나 DB 저장이 실패하면 새 버전을 현재 버전으로 지정하지 않는다. 이미 Drive에 올라간 불완전 파일은 비공개 실패 폴더로 남기고 조치 대상으로 기록하며 자동 삭제하지 않는다.

## 7. 관리자 화면

콘텐츠 상세에 다음 기능만 추가한다.

- `Drive 패키지 가져오기`: 관리자 수동 실행과 결과 표시
- `Canva에서 보기`: 기존 외부 링크 유지
- `수정본 업로드`: 파일 선택, 순서 확인, 규격 검증 결과 표시
- 버전 이력: 생성 주체, 생성 시각, 수정 메모, 카드 수 표시

오류는 누락 파일, 잘못된 카드 수, 규격, CTA, UTM, 일정, 중복 여부를 구체적으로 표시한다. 다른 관리자 화면과 콘텐츠 조회는 실패한 import 때문에 막히지 않는다.

## 8. 보안과 오류 처리

- 모든 관리자 API는 기존 관리자 세션 검사를 재사용한다.
- 예약 API는 기존 Cron secret 검증을 재사용한다.
- 업로드 파일명은 표시용으로만 보존하고 경로나 Drive 대상 계산에 사용하지 않는다.
- JSON, 텍스트와 이미지에 각각 크기 제한을 둔다.
- Drive API timeout과 재시도 가능 오류를 구분하되, DB transaction은 외부 네트워크 호출을 기다리지 않는다.
- 로그에는 Drive 파일 ID의 최소 식별 정보만 남기고 인증 헤더, private key, 원고 본문과 파일 bytes를 남기지 않는다.

## 9. 검증과 완료 조건

- 정상 패키지가 정확히 한 콘텐츠 버전과 순서가 보존된 자산으로 등록된다.
- 누락 파일, 알 수 없는 필드, 잘못된 CTA·UTM·채널·시각을 거부한다.
- 3장·9장, PNG가 아닌 파일과 잘못된 규격을 거부하고 4~8장은 허용한다.
- 수동과 예약 가져오기의 동시 요청이 한 번만 성공한다.
- Canva 수정본은 새 버전이 되며 이전 버전과 파일은 변하지 않는다.
- 비로그인 API 접근과 운영 폴더 밖 파일 참조를 거부한다.
- 자동 발행 비활성 상태가 유지되고 외부 채널 POST는 발생하지 않는다.
- 단위·통합 테스트, TypeScript, lint와 Production 조회 회귀 검증을 통과한다.

Production 반영은 별도 PR의 검사를 통과한 뒤 사용자 승인을 받아 수행한다.
