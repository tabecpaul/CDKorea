# Career Direct Korea 관리자 카드뉴스 미리보기 설계

## 1. 목적

관리자가 콘텐츠를 최종 승인하기 전에 현재 승인 대상 버전의 카드뉴스 실물을
대시보드에서 순서대로 확인하고, 그대로 승인할지 Canva에서 수정할지 판단할 수 있게
한다. 기존 파일 정보만 표시하는 불완전한 검토 화면을 보완한다.

## 2. 범위

### 포함

- 관리자 인증 안에서 현재 콘텐츠 버전의 PNG 미리보기
- 카드 position 순서대로 4~8장 표시
- 각 카드의 페이지 번호, 파일명과 크기 정보 표시
- 화면 너비에 맞는 미리보기와 클릭 시 브라우저 새 탭에서 큰 이미지 확인
- 이미지 로드 실패를 카드별로 명확히 표시
- 기존 Canva 링크와 수정본 업로드 흐름 유지
- 오래된 `미리보기 URL 연결은 Drive 가져오기 단계에서 추가됩니다` 안내 제거

### 제외

- 공개 Drive 링크와 Drive 파일·폴더 ID 노출
- 다운로드 버튼 또는 attachment 응답
- 이미지 편집 기능
- Drive Cron, Meta 임시 공개 URL과 외부 게시
- 승인 상태, 승인 스냅샷 또는 채널 일정의 자동 변경
- 이전 버전 선택·비교 UI

브라우저에 표시된 이미지는 기술적으로 사용자가 저장할 수 있다. 이번 제한은 별도
다운로드 버튼과 공개·영구 URL을 제공하지 않는다는 의미이며, 화면 캡처나 브라우저의
저장 기능까지 통제한다고 표현하지 않는다.

## 3. 선택한 방식

동일 출처의 관리자 인증 프록시를 사용한다.

```text
관리자 상세 화면
  → /api/admin/marketing/{contentId}/assets/{assetId}/preview
  → 관리자 세션 확인
  → content.currentVersionId와 asset.versionId 관계 확인
  → Drive 운영 폴더 소속과 저장 메타데이터 확인
  → Drive PNG bytes 전달
```

Drive 공개 링크는 만들지 않는다. Meta 게시용으로 계획된 승인 이미지 서명 URL과도
분리한다. 관리자 검토용 URL은 로그인 세션이 없으면 항상 거부된다.

## 4. 서버 검증

새 관리자 GET route는 다음을 모두 확인한다.

1. 기존 `hasAdminSession()`을 통과함
2. content ID와 asset ID가 양의 safe integer임
3. 콘텐츠가 존재하고 `currentVersionId`가 있음
4. 자산이 현재 버전에 속함
5. DB의 MIME이 `image/png`이고 크기가 기존 이미지 상한 이내임
6. Drive 메타데이터의 파일 ID, MIME과 크기가 DB 기록과 일치함
7. 파일이 설정된 마케팅 운영 폴더 아래에 있음
8. 다운로드한 bytes가 PNG signature를 가짐
9. 다운로드한 bytes의 SHA-256이 DB에 저장된 승인 후보 해시와 일치함

현재 버전이 바뀌면 이전 URL의 asset ID는 같은 콘텐츠 URL에서도 관계 검증에 실패해
더 이상 표시되지 않는다. 승인 전 `review_pending` 버전과 승인된 현재 버전을 모두 볼
수 있지만, 이전 버전이나 다른 콘텐츠 자산은 볼 수 없다.

## 5. 응답 보안

성공 응답:

- `Content-Type: image/png`
- `Content-Length`: 검증된 byte 길이
- `Content-Disposition: inline`
- `Cache-Control: private, no-store`
- `X-Content-Type-Options: nosniff`
- 파일명은 Content-Disposition에 포함하지 않음

오류 응답은 일반화된 코드만 반환한다. Drive 파일 ID, 폴더 ID, 서비스 계정, 원본
Drive 오류와 스택은 응답에 포함하지 않는다. 미리보기 route는 GET만 제공하며 DB나
Drive를 변경하지 않는다.

## 6. 화면 설계

기존 `카드뉴스 이미지` 영역을 실제 미리보기 갤러리로 교체한다.

- 모바일: 한 열
- 넓은 화면: 두 열
- 각 카드: 상단 `01`, `02` 같은 position, 중앙 실제 이미지, 하단 파일명·크기
- 이미지는 원래 4:5 비율을 유지하고 전체 카드가 잘리지 않게 표시
- 이미지 클릭: 같은 인증 URL을 새 탭에서 열어 큰 크기로 확인
- 로드 실패: 해당 위치에 `미리보기를 불러오지 못했습니다`와 페이지 번호 표시
- 갤러리 위 안내: `현재 승인 대상 vN · 카드 N장`
- Canva 링크와 `Canva 수정본 업로드`는 기존 위치와 동작을 유지

이미지 자체에 최종 승인 버튼을 추가하지 않는다. 기존 `검토 결정`이 단일 승인
진입점으로 남는다.

## 7. 데이터 흐름과 상태 불변

페이지 서버 조회는 이미 보유한 asset ID, position과 표시용 메타데이터만 UI에
전달한다. 브라우저가 각 관리자 preview URL을 요청하면 서버가 그 시점의 현재 버전과
Drive 파일을 재검증한다.

미리보기 성공과 실패는 다음을 변경하지 않는다.

- `marketing_content_versions.status`
- `approved_snapshot_hash`
- `marketing_approvals`
- `marketing_channel_schedules`
- `marketing_audit_logs`

감사 로그도 추가하지 않는다. 단순 이미지 조회 로그가 운영 결정을 의미하지 않기
때문이다.

## 8. 오류 처리

- 비로그인: 401
- 잘못된 ID: 400
- 콘텐츠·현재 버전·자산 관계 없음: 404
- MIME, 크기, PNG signature 또는 SHA-256 불일치: 409
- Drive 인증·접근·일시 오류: 세부정보를 숨긴 502

한 카드의 실패가 다른 카드 표시를 막지 않는다. 실패는 승인 상태를 자동 변경하지
않지만, 관리자는 모든 카드를 확인하지 못한 상태에서 승인하지 않도록 화면 메시지를
통해 안내받는다. 기존 승인 API의 규칙은 이번 작업에서 변경하지 않는다.

## 9. 검증 기준

자동 테스트:

1. 관리자 인증 없는 preview 요청 차단
2. 다른 콘텐츠와 이전 버전 자산 차단
3. DB와 Drive MIME·크기 불일치 차단
4. PNG signature와 SHA-256 불일치 차단
5. 올바른 현재 버전 PNG의 inline 응답과 보안 헤더 확인
6. 서버 코드가 Drive 공개 URL을 만들지 않음을 확인
7. 미리보기에서 DB update·insert가 발생하지 않음을 확인
8. 갤러리에 순서, 이미지, 파일 정보와 실패 문구가 존재함을 확인
9. 기존 승인·업로드·네이버 완료 테스트 회귀 없음

Production 확인:

1. 관리자 로그인 상태에서 현재 콘텐츠의 카드 8장이 순서대로 보임
2. 첫 카드와 마지막 카드를 새 탭에서 크게 확인 가능
3. Canva 링크와 수정본 업로드가 그대로 작동함
4. 비로그인 요청은 이미지를 반환하지 않음
5. 최종 승인, 채널 일정과 게시 상태가 미리보기 때문에 바뀌지 않음

## 10. 완료 후 운영

Production 검증 후 통합 운영 백로그에서 관리자 미리보기를 완료 항목으로 기록한다.
그다음 관리자는 대시보드의 실물을 기준으로 `Canva 수정 → 새 버전 업로드` 또는
`최종 승인`을 선택한다. Meta와 Drive Cron 관련 보류 상태는 그대로 유지한다.
