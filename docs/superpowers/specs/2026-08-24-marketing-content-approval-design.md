# 마케팅 콘텐츠 승인 흐름 보완 설계

## 목적

관리자 마케팅 상세 화면에서 이미 정의된 콘텐츠 승인 상태를 실제로 처리할 수 있게 한다. 이는 새로운 운영 흐름을 추가하는 작업이 아니라 기존 `marketing_approvals`, `approvedSnapshotHash`, 상태 머신의 `review_pending → approved/revision_requested` 경로를 완성하는 보완 작업이다.

## 범위

- 현재 버전의 최종 승인
- 현재 버전의 수정 요청과 필수 메모
- 승인 스냅샷 해시 생성과 저장
- 승인자·승인 시각·감사 로그 기록
- 관리자 상세 화면의 두 동작과 결과 표시
- 인증, 상태 전환, 중복 요청과 회귀 테스트

다음은 범위 밖이다.

- 자동 게시 또는 외부 채널 API 호출
- 채널 일정의 `scheduled` 전환
- Drive Cron 활성화
- 새로운 승인 단계나 역할 체계
- 게시 완료 처리

## 선택한 접근

서버 전용 승인 서비스와 관리자 API를 추가하고, 기존 상세 화면에 작은 클라이언트 액션 컴포넌트를 연결한다. 승인 로직을 UI나 라우트에 직접 넣지 않고 트랜잭션 서비스에 모아 상태 검증과 감사 기록을 한 곳에서 처리한다.

검토했던 다른 방식은 다음과 같다.

1. 승인 시 채널 일정도 `scheduled`로 변경: 콘텐츠 승인과 게시 준비가 혼동되므로 제외한다.
2. DB를 직접 수정하는 운영 우회: 승인 스냅샷과 감사 로그가 누락되므로 제외한다.

## 데이터 흐름

### 최종 승인

1. 관리자가 `최종 승인`을 누른다.
2. API는 관리자 세션과 양의 정수 콘텐츠 ID를 검증한다.
3. 트랜잭션 안에서 콘텐츠의 현재 버전을 다시 읽고 행 잠금으로 경쟁 요청을 직렬화한다.
4. 현재 버전이 `review_pending`인지 확인한다.
5. 현재 문안, 이미지 해시의 순서, CTA, 채널별 UTM과 발행 시각으로 결정적 승인 스냅샷을 만든다.
6. SHA-256 해시를 계산해 `marketing_approvals`에 `approved` 기록을 추가하고 버전의 `approvedSnapshotHash`와 상태 `approved`를 갱신한다.
7. 기존 활성 승인이 있다면 중복 승인을 만들지 않고 동일 결과를 반환한다. 다른 스냅샷의 이전 활성 승인은 `superseded`로 정리한다.
8. `marketing_audit_logs`에 승인 이벤트를 기록한다.
9. 채널 일정은 `approval_pending`, `manual` 그대로 둔다.

### 수정 요청

1. 관리자가 수정 메모를 입력하고 `수정 요청`을 누른다.
2. API는 공백 제거 후 1–1000자의 메모와 관리자 세션을 검증한다.
3. 현재 버전이 `review_pending`인지 확인한다.
4. 버전 상태를 `revision_requested`로 바꾸고 수정 메모를 저장한다.
5. 활성 승인 기록이 있다면 취소하되, 이미 게시된 채널 상태는 변경하지 않는다.
6. 감사 로그를 기록한다.

## 승인 스냅샷

기존 `ApprovalSnapshot` 구조를 사용한다.

- 문안: 네이버, Meta, Threads를 정해진 순서로 직렬화한 SHA-256
- 이미지: `position` 순서의 기존 `sha256` 배열
- CTA: 콘텐츠의 `ctaKind`
- UTM: 기존 `marketingChannels` 순서
- 일정: 각 `scheduledAt`의 ISO 문자열

정규화된 스냅샷 전체를 다시 SHA-256으로 계산해 `snapshotHash`와 `approvedSnapshotHash`에 동일하게 저장한다.

## API와 UI

- `POST /api/admin/marketing/[id]/approval`
  - `{ action: "approve" }`
  - `{ action: "request_revision", note: string }`
- 성공 후 상세 화면을 새로고침해 서버의 실제 상태를 표시한다.
- `review_pending`일 때만 버튼을 활성화한다.
- 수정 요청 메모는 해당 동작에만 필수다.
- 승인 버튼 문구는 `최종 승인`, 수정 버튼 문구는 `수정 요청`으로 고정한다.
- UI는 승인만으로 게시되지 않으며 모든 채널이 수동이라는 안내를 버튼 가까이에 표시한다.

## 오류 처리와 안전성

- 미인증: 401
- 잘못된 콘텐츠 ID 또는 요청: 400
- 콘텐츠·현재 버전 없음: 404
- 허용되지 않은 상태 또는 오래된 요청: 409
- 서버 내부 오류: 운영 세부정보를 숨긴 500
- API는 요청 시점에 현재 버전을 다시 읽어 화면의 오래된 상태를 신뢰하지 않는다.
- 승인과 수정 요청 모두 외부 네트워크 게시 호출을 하지 않는다.

## 테스트와 완료 조건

- 스냅샷은 동일 입력에 동일 해시를 생성하고 이미지·문안·CTA·UTM·일정 변경을 감지한다.
- `review_pending`만 승인 또는 수정 요청할 수 있다.
- 승인 시 버전과 승인 기록은 `approved`, 해시는 일치한다.
- 채널 일정은 승인 후에도 `approval_pending`과 `manual`이다.
- 수정 요청은 메모를 저장하고 `revision_requested`가 된다.
- 중복 승인 요청은 승인 기록을 중복 생성하지 않는다.
- 미인증·잘못된 입력·경쟁 상태를 거부한다.
- 기존 Drive 가져오기, 이미지 버전 업로드, 관리자 목록과 Production 빌드가 회귀하지 않는다.

## 운영 적용

PR과 Production 검증 후 현재 `은사·재능·강점` v1에 관리자가 다시 최종 승인을 실행한다. 승인 뒤에도 실제 게시와 게시 완료 기록은 별도의 수동 운영 단계로 남는다.
