# Career Direct Korea 주간 콘텐츠 일정 정합성 검증 설계

- 상태: 사용자 설계 승인
- 기준: 기존 마케팅 콘텐츠 대시보드와 Drive 패키지 가져오기 구조 보완
- 범위: 운영 문서 정비와 게시 전 자동 검증

## 1. 목적

승인된 주간 콘텐츠 일정이 이메일에는 존재하지만 Drive 패키지와 대시보드 캘린더에는 누락되는 문제를 발행 전에 발견한다. 기존 대시보드의 의미와 콘텐츠 담당 역할은 유지하며, 새 콘텐츠 생성이나 자동 게시 기능을 추가하지 않는다.

## 2. 기존 동작과 보완 범위

대시보드 캘린더는 Drive의 `content-package.json`이 정상적으로 import되어 DB에 생성된 채널 일정만 표시한다. `launch-plan.md`나 이메일 일정만으로는 캘린더 항목이 생성되지 않는다.

이번 보완은 다음 두 작업으로 제한한다.

1. 충돌하거나 구현보다 앞서간 운영 문구를 수정한다.
2. 주간 알림 전 승인 일정, Drive manifest, import 결과를 비교해 누락을 보고한다.

대시보드에 가상의 미임포트 행을 만들거나 새 상태를 추가하지 않는다. Meta 및 네이버 게시 동작도 변경하지 않는다.

## 3. 기준 자료와 우선순위

정합성 검증은 다음 자료를 서로 다른 역할의 증거로 사용한다.

1. 승인된 주간 일정: 이번 주에 준비해야 하는 콘텐츠의 기준
2. 캠페인 `launch-plan.md`: 저장소에 보존된 일정 근거
3. Drive `content-package.json`: import 가능한 완성 패키지의 기준
4. 대시보드 DB 일정: 실제 import 완료의 기준
5. 발행 완료 기록: 과거 수동 발행 또는 채널 게시 완료의 기준

자료가 충돌하면 가장 최근의 명시적 관리자 승인을 우선한다. 출처가 확인되지 않은 일정은 임의로 캠페인에 배정하지 않는다.

## 4. 캠페인 구분

저장소와 Drive 폴더는 캠페인별로 분리해 사람이 찾기 쉽게 유지한다. 기술적인 캠페인 구분과 중복 방지는 manifest의 다음 값을 기준으로 한다.

- `campaignKey`: 캠페인 소속
- `packageId`: 패키지 전역 고유 식별자
- `slug`: 콘텐츠 고유 식별자

폴더 경로만으로 캠페인이 분리된다고 판단하지 않는다. `campaignKey`가 승인 일정의 캠페인과 다르거나 `packageId`·`slug`가 충돌하면 import 준비 완료로 인정하지 않는다.

## 5. 주간 검증 흐름

매주 금요일 오전 10시 KST의 검토 이메일을 보내기 전에 다음 순서로 검사한다.

1. 다음 운영 주간의 승인된 일정과 관련 `launch-plan.md` 항목을 모은다.
2. Drive 운영 폴더에서 같은 주간의 manifest를 조회한다.
3. manifest의 캠페인, 콘텐츠, 채널 일정과 CTA·UTM을 기존 검증기로 확인한다.
4. 실제 import 결과와 대시보드 일정을 확인한다.
5. 각 항목을 아래 세 보고 그룹 중 하나로 분류한다.
6. 준비·임포트 누락이 하나라도 있으면 정상 완료 이메일처럼 보고하지 않고 조치 항목을 명시한다.

검증은 기존 import 서비스의 성공·중복·실패 결과와 감사 기록을 재사용한다. 같은 콘텐츠를 다시 생성하거나 중복 import하지 않는다.

## 6. 보고 상태

### 임포트 완료

승인 일정, manifest와 DB 일정이 일치한다. 관리자 검토 대상과 수동 발행 확인사항을 이메일에 표시한다.

### 준비·임포트 누락

다음 중 하나에 해당한다.

- 승인 일정은 있지만 패키지가 없음
- manifest는 있지만 import되지 않음
- manifest 검증 또는 import가 실패함
- 캠페인 키, slug, 일정 또는 채널이 승인 일정과 다름
- 일정의 출처나 패키지 소속을 확인할 수 없음

원인을 `패키지 미생성`, `임포트 실패`, `식별자 불일치`, `출처·패키지 미확인`으로 구체적으로 보고한다.

### 발행 완료·보류

이미 수동 발행 또는 게시 완료된 과거 항목과 관리자가 보류한 항목이다. 현재 준비 누락에 포함하지 않으며, 근거가 없는 상태 변경은 하지 않는다.

## 7. 현재 확인 항목의 처리

- 2026-08-18과 2026-08-23은 수동 발행 완료 사실을 기준으로 과거 이력으로 분류한다. 별도 승인 없이 패키지나 대시보드 이력을 새로 만들지 않는다.
- 2026-08-27은 현재 저장소에 완성 패키지가 있는 항목으로 검증한다.
- 2026-08-24, 2026-08-26, 2026-08-28에 언급된 제목은 현재 저장소에서 일정·원고·패키지 출처가 확인되지 않았다. 관리자 승인 기록 또는 ChatGPT Work 산출물에서 근거가 확인될 때까지 `출처·패키지 미확인`으로 보고하고 임의로 캠페인을 지정하지 않는다.

## 8. 콘텐츠와 채널 제약

- ChatGPT Work는 기존 책임에 따라 콘텐츠를 준비하고 Drive 패키지를 만든다.
- Codex는 manifest, import, 대시보드와 알림의 기술적 정합성을 담당한다.
- 관리자는 최종 승인과 수동 게시를 담당한다.
- 네이버는 장문 텍스트 원고와 하단 단일 CTA를 사용하며 편집기에서 링크를 직접 연결하고 모바일 클릭을 확인한다.
- Threads에는 카드뉴스를 요구하지 않는다.
- Facebook과 Instagram 카드뉴스는 기본 5장이고, 최상위 디자인 기준에 따라 필요한 경우 4~8장을 허용한다.
- 이번 작업은 새 콘텐츠 작성, 일정 자동 확정, 네이버 자동 발행, Meta 자동 게시 활성화를 포함하지 않는다.

## 9. 실패 처리와 알림

- Drive 조회 실패와 import 실패는 콘텐츠 없음으로 숨기지 않고 `준비·임포트 누락`과 기술 오류를 함께 보고한다.
- 이메일 발송 실패는 정합성 결과와 별도로 기록한다.
- 검증 대상이 없으면 정상 no-op으로 기록하되, 승인된 일정이 있는데 대상이 0건이면 no-op으로 처리하지 않는다.
- 하나의 콘텐츠 오류가 다른 정상 콘텐츠의 조회와 보고를 막지 않게 한다.

## 10. 완료 조건

- 기존 운영 문서에서 폴더 경로가 기술적 캠페인 분리를 보장한다는 표현이 제거된다.
- 구현되지 않은 대시보드 `missing_import` 상태를 현재 기능처럼 설명하지 않는다.
- 주간 검증 결과가 `임포트 완료`, `준비·임포트 누락`, `발행 완료·보류`로 구분된다.
- 승인 일정이 있는데 패키지 또는 DB 일정이 없으면 검증이 성공으로 끝나지 않는다.
- 과거 발행 완료 항목은 현재 제작 누락으로 잘못 계산되지 않는다.
- 콘텐츠·CTA·채널별 표시와 카드 장수의 기존 확정 기준이 유지된다.
- 자동 게시와 외부 채널 변경이 발생하지 않는다.
