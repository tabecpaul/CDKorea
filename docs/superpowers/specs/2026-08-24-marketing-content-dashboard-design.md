# Career Direct Korea 마케팅 콘텐츠 대시보드 설계

## 1. 목적

Career Direct Korea의 콘텐츠 일정, 원고, 이미지, CTA, UTM, 승인, 발행 결과가 이메일·Google Drive·저장소·예약 작업에 흩어진 문제를 해결한다. 1인 운영자가 기존 관리자 화면에서 전체 마케팅 운영을 한눈에 확인하고, 최종 승인한 콘텐츠만 Facebook, Instagram, Threads에 예약 발행할 수 있게 한다.

이 설계는 기존 목표, 브랜드, 운영 책임과 사용자 변경사항을 보존한다. 콘텐츠 자동 승인, 네이버 블로그 자동 발행, 광고 자동 운영, 고객 기록 자동화는 포함하지 않는다.

## 2. 확정된 책임 분장

### ChatGPT Work

- 매주 금요일 오전 10시(Asia/Seoul)에 다음 주 콘텐츠를 준비한다.
- 승인된 기존 일정을 우선 처리한다.
- 일정이 소진되면 신규 주제, CTA, 발행 일정안을 제안한다.
- 승인 전에는 신규 제안을 발행 가능한 최종 콘텐츠로 확정하지 않는다.
- 승인 후 원고, 채널별 문안, 이미지, CTA, UTM과 체크리스트를 준비한다.
- Google Drive에 산출물을 저장하고 대시보드에 `검토 대기` 버전을 등록한다.

### Codex

- 저장소, 관리자 화면, Supabase, Vercel, Meta 연결, 예약 작업, 보안과 장애 대응을 담당한다.
- 정기 콘텐츠를 대신 만들거나 승인하지 않는다.

### 관리자

- 신규 주제, CTA와 일정의 최종 결정권을 가진다.
- 콘텐츠 버전을 수정 요청, 승인 또는 승인 취소한다.
- 네이버 블로그를 직접 발행하고 모바일 링크를 확인한다.

## 3. 범위

### 포함

- 기존 관리자 영역의 마케팅 대시보드
- 콘텐츠 캘린더, 버전, 승인, 채널별 일정과 발행 상태
- Google Drive 이미지와 Canva 편집 원본 연결
- 사용자 수정 PNG 업로드와 버전 관리
- Facebook, Instagram, Threads 승인 후 예약 발행
- 채널별 실패, 재시도, 게시물 URL과 감사 이력
- 기존 관리자 화면의 공통 레이아웃과 전환 체감 성능 개선

### 제외

- 네이버 블로그 자동 발행
- 승인 없는 콘텐츠 생성 확정 또는 게시
- Meta 광고 생성, 재개, 예산 변경과 성과 자동 판단
- 실제 첫 고객 상담 전 고객 기록 자동화
- Canva 최신본 자동 동기화

## 4. 기술 방향

기존 `apps/www` 관리자 인증과 운영 환경을 확장한다. 별도 관리자 앱이나 로그인을 만들지 않는다.

- Supabase: 콘텐츠, 버전, 일정, 승인, 연결 상태와 발행 결과의 기준 저장소
- Google Drive: 카드뉴스, 이미지, 첨부 파일과 편집 원본
- GitHub 저장소: 브랜드 기준, 템플릿과 운영 규칙
- Vercel: 관리자 애플리케이션, 예약 실행과 서버 측 Meta 연동
- Meta 공식 API: Facebook, Instagram, Threads 게시

외부 예약 서비스나 범용 자동화 플랫폼을 운영 기준으로 추가하지 않는다. 운영 상태와 실패 원인을 자체 대시보드 한 곳에 유지한다.

## 5. 관리자 정보 구조

### `/admin/marketing`

#### 이번 주 운영 요약

- 검토 대기
- 수정 요청
- 승인 완료
- 오늘 발행 예정
- 발행 실패
- 채널 연결 상태

#### 콘텐츠 캘린더

- 네이버, Facebook, Instagram, Threads 일정 통합 표시
- 콘텐츠별 채널, 발행 시각과 자동·수동 구분
- 미승인 일정은 예정 시각이 지나도 게시하지 않음

#### 콘텐츠 상세

- 네이버 장문 원고
- Facebook·Instagram 공용 문안
- Threads 연결 글
- 카드뉴스 미리보기와 Canva 링크
- 단일 CTA와 채널별 UTM
- 버전 비교
- `Canva에서 수정`, `수정본 업로드`, `수정 요청`, `최종 승인`, `승인 취소`
- 채널별 발행 상태, 오류와 게시물 URL

#### 운영·연결

- Facebook 페이지, Instagram 프로페셔널 계정, Threads 프로필 연결 상태
- 토큰 만료와 권한 부족
- Gmail, Drive와 예약 실행 상태
- 최근 실패와 재시도 결과

## 6. 상태 모델

콘텐츠 기본 흐름은 다음과 같다.

`제안 → 제작 중 → 검토 대기 → 수정 요청 → 검토 대기 → 승인 완료 → 예약됨 → 발행 완료`

채널 상태는 콘텐츠 상태와 별도로 관리한다.

- 준비 중
- 승인 대기
- 예약됨
- 발행 중
- 발행 완료
- 발행 실패
- 조치 필요
- 수동 발행 완료
- 승인 기한 경과

일부 채널 실패가 콘텐츠 전체를 실패로 바꾸지 않는다.

- 지정된 단일 CTA
- 실제 네이버 카테고리
- 현재 상태와 최신 버전

### `marketing_content_versions`

- Drive 폴더와 Canva 디자인 링크
- 카드 장수, 순서와 이미지 목록
- 승인 시점의 파일 식별자와 무결성 해시
- 생성 주체와 수정 이유

### `marketing_channel_schedules`

- 채널과 발행 시각
- 채널별 UTM
- 자동 또는 수동 발행 구분
- 승인, 예약, 발행과 실패 상태

### `marketing_approvals`

- 승인 대상 버전
- 승인과 취소 시각
- 관리자 활동 이력

### `marketing_publish_attempts`

- 고유 발행 키
- Meta 요청 결과와 오류 코드
- 재시도 횟수
- 게시물 ID, URL과 발행 시각

### `marketing_connections`

- 계정과 채널 식별자
- 권한 확인 상태와 토큰 만료 시각
- 비밀 토큰 원문은 저장하지 않음

공개 사용자와 `anon`, `authenticated` 역할에는 마케팅 운영 테이블 권한을 부여하지 않는다. 서버 측 관리자 경로만 접근한다.

## 8. 버전과 Canva 수정 흐름

1. ChatGPT Work가 카드별 PNG, 전체 미리보기, 편집 원본 또는 Canva 링크를 준비한다.
2. 대시보드는 이를 새 `검토 대기` 버전으로 표시한다.
3. 관리자는 그대로 승인하거나 `Canva에서 수정`을 선택한다.
4. Canva에서 수정한 뒤 카드별 PNG를 내보낸다.
5. `수정본 업로드`로 새 버전을 등록한다. 기존 버전은 삭제하지 않는다.
6. 카드 장수와 순서를 확인한 뒤 다시 검토한다.
7. 최종 승인 순간의 문안, 이미지, CTA, UTM과 발행 시각을 잠근다.

승인된 버전은 직접 수정하지 않는다. 문안, 이미지, CTA, UTM 또는 발행 시각이 바뀌면 새 버전을 만들고 기존 승인을 무효화하며 예약을 취소한다. Canva에서 이후 변경한 내용은 `새 수정본 가져오기`와 재승인 없이 게시본에 반영되지 않는다.

Drive 폴더나 Canva 원본이 나중에 바뀌어도 승인본이 달라지지 않도록 승인 시 파일 식별자와 무결성 해시를 저장하고, 발행 직전에 동일성을 다시 확인한다. Meta가 외부에서 가져갈 수 있는 미디어 URL이 필요한 경우 서버가 승인본에 한정된 임시 전달 URL을 만든다. Drive 폴더 자체를 공개하지 않는다.

카드뉴스는 `flexible-card-news-design-spec.md`를 최상위 기준으로 사용한다. 기본은 5장이며 메시지 구조에 따라 4~8장을 허용한다.

## 9. 제작과 승인 흐름

### 주간 준비

1. ChatGPT Work가 승인 일정과 발행 이력을 대조한다.
2. 다음 주 자료를 Drive 주차별 폴더에 저장한다.
3. 대시보드에 검토 대기 버전을 등록한다.
4. 관리자에게 검토 이메일을 보낸다.
5. 승인 일정이 없으면 신규 주제·CTA·일정안만 제안한다.

### 관리자 검토

- 수정 요청: ChatGPT Work가 새 버전을 준비한다.
- Canva 수정: 관리자가 편집하고 PNG를 새 버전으로 업로드한다.
- 최종 승인: 특정 버전과 채널별 예약을 고정한다.
- 승인 취소: 아직 발행되지 않은 예약을 취소한다.

## 10. 자동 발행

Vercel 예약 작업은 1분 간격을 목표로 발행 예정 항목을 확인한다. 운영 요금제나 플랫폼 제한으로 1분 실행을 보장할 수 없으면 Production 활성화 전에 관리자에게 실제 지연 범위를 제시하고 승인을 받는다. 다음 조건을 모두 만족한 채널만 처리한다.

- 지정 버전이 최종 승인됨
- 예정 시각에 도달함
- 해당 채널에 아직 게시되지 않음
- 계정 연결과 필요한 권한이 정상임

Facebook, Instagram, Threads를 독립적으로 처리한다. 각 요청은 고유 발행 키를 사용한다. 성공한 채널은 재실행하지 않고 실패한 채널만 최대 2회 재시도한다. 최종 실패는 `조치 필요`로 표시하고 이메일로 알린다.

게시 성공 시 플랫폼 게시물 ID, URL과 실제 발행 시각을 저장한다.

## 11. 네이버 수동 발행

- 대시보드가 원고, 이미지, CTA, UTM과 체크리스트를 제공한다.
- 사용자가 네이버 편집기에서 CTA 문구에 링크를 직접 연결한다.
- 모바일에서 목적지가 정상적으로 열리는지 확인한다.
- 사용자가 게시 URL을 입력하고 `수동 발행 완료`를 누른 경우에만 완료로 기록한다.

## 12. 오류 처리

- Drive 이미지 누락: 승인 차단
- CTA 또는 UTM 누락: 승인 차단
- Meta 연결 만료: 예약을 보존하고 발행 중지 및 관리자 알림
- 일부 채널 실패: 성공 채널 보존, 실패 채널만 재시도
- 중복 실행: 고유 발행 키로 차단
- 승인 파일 무결성 불일치: 예약 보존, 발행 중지와 재승인 요청
- 발행 시각 경과 후 미승인: `승인 기한 경과`, 자동 발행 없음
- 카드 순서 또는 장수 오류: 검토 대기 유지
- 이메일 실패: 게시 결과와 분리하여 대시보드 조치 항목으로 표시

## 13. 성능 설계

기존 관리자 화면은 페이지 이동마다 전체 서버 조회를 기다린다. 마케팅 화면 추가와 함께 이 구조를 개선한다.

- 공통 관리자 레이아웃과 메뉴를 화면에 유지한다.
- 메뉴 클릭 즉시 선택 상태와 로딩 골격을 표시한다.
- 영역별 데이터는 독립적으로 스트리밍한다.
- 분석 집계는 짧게 캐시한다.
- 콜백과 콘텐츠 목록은 페이지 단위로 조회한다.
- 다음 관리자 경로를 미리 불러온다.
- 이미지 원본 대신 작은 미리보기를 사용한다.
- 영역별 오류가 전체 화면을 막지 않게 한다.

체감 목표:

- 클릭 후 전환 피드백: 즉시
- 기본 화면과 로딩 골격: 0.5초 이내
- 일반 데이터: 1.5초 이내
- 무거운 분석 조회는 다른 메뉴 사용을 차단하지 않음

마케팅, 콜백과 전환 분석 쿼리를 분리하여 새 기능이 기존 화면 조회량을 증가시키지 않게 한다.

## 14. 보안과 운영 환경

- 기존 관리자 세션을 재사용한다.
- Meta 토큰과 Drive 인증정보는 Vercel 환경변수에 보관한다.
- 비밀값을 브라우저나 Supabase 공개 응답에 노출하지 않는다.
- 승인, 취소와 재발행을 감사 이력에 남긴다.
- 개발과 Production의 데이터, 토큰과 게시 대상을 분리한다.
- 마이그레이션 직전에 Production Supabase ref가 `fytkptzbnhfsqsktmzpx`인지 다시 검증한다.

Facebook 페이지, Instagram 프로페셔널 계정과 Threads 프로필이 같은 Meta 비즈니스 포트폴리오 또는 계정 센터에 연결되었다고 추정하지만 확정하지 않는다. 구현 전에 다음을 읽기 전용으로 검증한다.

- 페이지와 프로필 ID
- 관리자와 게시 권한
- 필요한 액세스 토큰과 권한 범위
- 테스트 게시 없이 확인 가능한 API 접근 상태

검증 전에는 Production 자동 발행을 활성화하지 않는다.

## 15. 검증과 테스트

- 상태 전이와 승인 무효화 단위 테스트
- 버전 잠금과 승인 취소 테스트
- 고유 발행 키와 중복 실행 테스트
- 채널별 부분 성공과 재시도 테스트
- 만료 토큰과 권한 부족 테스트
- Drive 누락, 잘못된 장수와 순서 테스트
- 관리자 인증과 공개 접근 차단 테스트
- 관리자 메뉴 전환 시간과 데이터 표시 시간 측정
- 모바일과 데스크톱 화면 검증

실제 자동 발행은 다음 순서로 활성화한다.

1. 계정과 권한 읽기 전용 검증
2. 테스트 모드에서 예정 발행 페이로드만 기록
3. 관리자 검토
4. Facebook 최소 테스트 게시
5. Instagram 최소 테스트 게시
