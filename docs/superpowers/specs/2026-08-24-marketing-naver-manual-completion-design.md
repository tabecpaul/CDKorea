# Career Direct Korea 네이버 수동 발행 완료 설계

## 1. 목적

승인된 네이버 콘텐츠를 관리자가 대시보드 한곳에서 확인하고 직접 발행한 뒤,
필수 링크 점검과 실제 게시 URL을 근거로 완료 상태를 기록한다. 이 기능은 네이버
발행을 자동화하지 않으며 Facebook, Instagram과 Threads의 상태를 변경하지 않는다.

## 2. 범위

### 포함

- 현재 승인된 버전의 네이버 원고, 카드뉴스 파일 순서, 네이버 카테고리, CTA와 UTM 표시
- `CTA 문구에 링크 직접 연결` 확인
- `모바일에서 신청 화면 정상 확인` 확인
- 실제 `blog.naver.com` 게시 URL 입력과 검증
- 네이버 일정의 `manual_published` 전환
- 게시 URL, 실제 완료 시각과 감사 로그 저장
- 이미 완료된 게시 정보의 읽기 전용 표시

### 제외

- 네이버 편집기 조작과 자동 게시
- 네이버 로그인 또는 API 연동
- 원고·이미지·CTA·UTM 수정
- 콘텐츠 승인 또는 승인 취소
- Facebook, Instagram과 Threads 상태 변경
- Meta 게시 API, Drive Cron과 Production 자동 발행 활성화

## 3. 화면 구조

기존 콘텐츠 상세 화면에 `네이버 수동 발행` 패널 하나를 추가한다. 별도 관리자
메뉴나 페이지는 만들지 않는다.

패널은 다음 순서로 표시한다.

1. 승인된 현재 버전과 네이버 예약 시각
2. 네이버 카테고리
3. 복사 가능한 네이버 원고
4. 카드뉴스 파일의 승인된 순서와 파일 정보
5. 네이버 일정에 저장된 CTA·UTM URL
6. 발행 전 체크리스트 두 항목
7. 게시 URL 입력과 `수동 발행 완료` 버튼

완료된 일정은 입력 기능을 비활성화하고 게시 URL과 완료 시각을 표시한다. 기존
채널별 일정 영역은 유지하되 동일 네이버 완료 상태를 반영한다.

## 4. 활성 조건

완료 입력은 다음 조건을 모두 만족할 때만 활성화한다.

- 현재 콘텐츠 버전의 상태가 `approved`
- 해당 현재 버전에 `naver` 일정이 정확히 하나 존재
- 네이버 일정의 mode가 `manual`
- 네이버 원고가 비어 있지 않음
- UTM URL이 비어 있지 않음
- 승인 스냅샷 해시가 존재함
- 일정 상태가 아직 `manual_published`가 아님

승인 전, 수정 요청 상태, 다른 버전의 일정 또는 자동 mode 일정은 완료 처리할 수
없다. 예정 시각이 지났다는 사실만으로 자동 완료하거나 승인 상태를 변경하지 않는다.

## 5. 요청과 검증

관리자 전용 엔드포인트는
`POST /api/admin/marketing/[id]/naver-complete`를 사용한다.

요청 본문은 다음 값만 받는다.

- `publishedUrl`: 사용자가 입력한 게시 URL
- `ctaLinked`: CTA 문구에 직접 링크를 연결했다는 확인값
- `mobileDestinationChecked`: 모바일 목적지를 확인했다는 확인값

서버는 관리자 세션, 양쪽 확인값, HTTPS, 사용자 정보가 없는 URL, 허용 host와
현재 승인 버전을 다시 검증한다. 허용 host는 승인 계획에 따라
`blog.naver.com`으로 제한한다. query와 fragment가 포함된 실제 게시 URL은 보존한다.

클라이언트 확인값만 신뢰하지 않고 모든 검증을 서버에서 반복한다.

## 6. 상태 변경과 데이터

기존 `marketing_channel_schedules` 필드를 사용하므로 DB migration은 추가하지 않는다.

- `status`: `manual_published`
- `published_url`: 검증된 네이버 게시 URL
- `published_at`: 서버가 완료 요청을 수락한 시각
- `updated_at`: 같은 서버 시각

완료 처리는 transaction 안에서 현재 콘텐츠, 현재 버전과 네이버 일정을 다시 잠그고
검증한다. 콘텐츠 버전 상태, 승인 기록과 다른 채널 일정은 변경하지 않는다.

감사 로그에는 콘텐츠·버전·일정 식별자, 관리자 actor, 작업명
`naver_manual_published`, 두 확인값과 게시 host만 기록한다. 원고, 전체 CTA URL,
전체 게시 URL과 비밀값은 감사 로그 상세에 중복 저장하지 않는다.

## 7. 중복과 오류 처리

- 같은 게시 URL로 이미 완료된 같은 일정의 재요청은 성공 응답을 반환하되 데이터를
  다시 쓰지 않는 idempotent 요청으로 처리한다.
- 이미 완료된 일정에 다른 URL을 보내면 충돌로 거부한다.
- 승인되지 않은 버전, 현재 버전 불일치, 네이버 일정 누락과 잘못된 mode는 충돌로
  거부한다.
- 두 체크 중 하나라도 없거나 URL이 잘못되면 검증 오류로 거부한다.
- DB 오류는 완료된 것처럼 표시하지 않고 일반 운영 오류를 반환한다.

## 8. 보안

- 기존 관리자 세션 검사를 재사용한다.
- 공개 역할은 마케팅 테이블에 접근하지 못하는 기존 RLS와 권한 회수를 유지한다.
- URL parser로 protocol과 hostname을 비교하며 문자열 포함 검사만 사용하지 않는다.
- 관리자 응답과 로그에 Drive 파일 ID, secret, 토큰 또는 원고 전체를 추가 노출하지 않는다.
- 외부 네이버 URL로 서버 요청을 보내지 않는다. URL은 기록만 하므로 SSRF가 발생하지 않는다.

## 9. 검증 기준

자동 테스트:

1. 비로그인 요청은 거부된다.
2. 두 확인값 또는 게시 URL이 없으면 완료되지 않는다.
3. HTTP, 사용자 정보 포함 URL과 비허용 host는 거부된다.
4. 승인된 현재 버전의 수동 네이버 일정만 완료된다.
5. 완료 후 URL과 서버 시각이 저장된다.
6. 같은 요청은 중복 저장하지 않는다.
7. 완료 후 다른 URL 변경은 거부된다.
8. Facebook, Instagram과 Threads 상태는 변하지 않는다.
9. 감사 로그가 남고 민감한 본문은 포함하지 않는다.

Production 확인:

1. 승인된 콘텐츠 상세 화면에서 원고, 카테고리, 카드 순서와 UTM을 확인한다.
2. 확인 항목과 URL이 없을 때 버튼이 비활성 또는 요청이 거부되는지 확인한다.
3. 실제 게시 후 두 확인과 `blog.naver.com` URL을 입력한다.
4. 상태가 `manual_published`로 표시되고 게시 링크와 완료 시각이 보이는지 확인한다.
5. 다른 세 채널의 상태가 그대로인지 확인한다.

## 10. 완료 후 다음 순서

이 단계가 Production에서 검증되면 통합 운영 백로그에 완료 상태를 반영한다. 그다음
ChatGPT Work 주간 패키지 연동 운영 검증으로 이동한다. Meta 관련 단계는 계정 문제와
사전 검증 조건이 해결될 때까지 계속 차단 상태로 둔다.
