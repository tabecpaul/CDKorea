# 운영 모니터 최신 성공 조회 오탐 수정 설계

## 문제

`latestSuccessfulRuns()`는 모든 모니터링 작업의 성공 기록을 최신순으로 최대 100개 조회한 뒤, 메모리에서 작업별 기록을 찾는다. `lead-emails`와 `callback-reminders`처럼 자주 실행되는 작업이 100개를 채우면 하루 한 번 실행되는 `operations-monitor`의 이전 성공 기록이 조회 결과에서 밀려난다. 이때 정상 실행 이력이 있어도 `성공 기록 없음`으로 판정되어 매일 오전 9시에 잘못된 경고가 발송될 수 있다.

## 변경 범위

- `latestSuccessfulRuns()`가 요청받은 각 작업 이름별로 최신 성공 기록 한 건을 직접 조회한다.
- 작업별 조회는 독립적이므로 동시에 실행한다.
- 반환 순서와 반환 형식은 기존 계약을 유지한다.
- Cron 주기, 지연 판정 기준, 알림 발송 흐름, 고객 데이터는 변경하지 않는다.

## 오류 처리

데이터베이스 조회 오류는 기존과 동일하게 호출자에게 전달한다. 특정 작업의 성공 기록이 실제로 없을 때만 `completedAt: null`을 반환한다.

## 검증

- 요청한 작업별 최신 성공 기록을 정확히 반환하는 단위 테스트를 추가한다.
- 다른 작업의 최신 성공 기록이 100개 이상 존재하는 상황에서도 `operations-monitor`의 이전 성공 기록이 유지되는 회귀 테스트를 추가한다.
- 운영 모니터 관련 테스트와 타입 검사를 실행한다.

## 완료 조건

- 오전 9시 운영 모니터 실행 시 전날의 정상 성공 기록을 찾는다.
- 실제 성공 기록이 없는 경우에만 `운영 모니터링 Cron 이상`이 표시된다.
- 기존 알림 및 관리자 화면의 데이터 계약이 바뀌지 않는다.
